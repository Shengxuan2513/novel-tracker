# 远程书籍版本下载协议

EPUB 是 ZIP 文件。远程阅读器缓存的章节偏移只对特定版本有效，原文件更新后不能继续用旧偏移读取新版文件。

OPDS acquisition 地址使用 `/api/download/version/<mtime_ns>-<size>/<filename>`；书籍的 Atom ID 仍由文件名生成，更新内容不改变 ID。相同文件未变时 URL 保持稳定。

- 当前版本：返回不可变的磁盘快照，通过 aiohttp FileResponse 支持 GET、HEAD、Range、ETag 和 HTTP 条件请求。
- 过期版本：返回 `410 Gone`，`Cache-Control: no-store`，并通过 `X-NovelTracker-Latest-URL` 返回同源相对地址。
- 文件不存在：返回 404。
- 原 `/api/download/<filename>` 保持兼容，直接提供当前文件；它不具备版本快照保证。

#5 中的配套阅读修复版支持该更新头，可在打开书籍检查版本时跟随最新地址。普通客户端收到 410 后需要刷新 OPDS 并重新获取；已经完整下载的手机副本仍需下载更新。
Atom ID 保持稳定避免目录将更新发布为新的条目，但客户端如何按 URL 去重/导入仍需手机实测。

首次读取每个文件版本时，后台线程将文件复制到下载目录的 `.download-snapshots/`。复制前后核对源文件状态；复制期间发生更新会拒绝本次读取并返回 410。发送时源文件再次变化也不会改变快照字节。同一版本后续请求复用快照。

快照会占用磁盘，每个被读取的版本约占原文件大小。当前不自动清理，以免删除正在发送的文件；需要回收空间时，先停止服务，再删除 `.download-snapshots/`，下次读取会重新生成。快照不进入 OPDS，也被 Git 忽略。

版本由纳秒修改时间和文件长度组成。写入程序必须更新修改时间；保留时间且长度完全相同的内容替换不能可靠识别。建议采用临时文件完整写入后原子替换的方式发布书籍。此协议不是内容哈希验证，也不能判断首次读取前是否已经存在未写完的文件。

验证：合成 EPUB 的真实 ZIP 章节偏移、过期地址及最新地址恢复、稳定 Atom ID、HTTP 条件请求、复制期间更新、复制后覆盖、中文及含百分号文件名、快照复用和路径边界。未包含手机实测。
